# ADR 0001: Four-Class Adverse Event Taxonomy Reduction

## Status
Accepted

## Context
Raw openFDA MAUDE records contain heterogeneous, noisy classification fields (`event_type`, `type_of_report`, and free-text narrative descriptions). Mapping all regulatory reporting permutations creates severe class imbalance and sparse label spaces unsuitable for deterministic routing under EU-MDR Annex III vigilance workflows.

## Decision
Collapse openFDA event records into four canonical regulatory categories:
- `D` (Death)
- `I` (Serious Injury)
- `M` (Malfunction)
- `O` (Other / Non-Serious)

Records are sanitized via `maude_classifier/text_cleaner.py` and partitioned deterministically via `ingestion/transform_and_split.py` into a canonical frozen split receipt: 129,422 total records (103,537 train / 12,942 val / 12,943 test).

## Consequences
- **Positive**: High class consistency, unambiguous regulatory escalation paths for vigilance officers.
- **Negative**: Nuanced clinical boundary conditions (e.g., potential vs. actual injury) are collapsed into discrete categorical labels.

# ADR 0002: Two-Tier Hierarchical Inference Architecture

## Status
Accepted

## Context
High-parameter clinical transformers (Bio_ClinicalBERT) provide domain precision but introduce container size, cold-start latency, and external endpoint dependency risks. Relying solely on a heavy model risks service downtime if the Vertex AI endpoint scales to zero or experiences quota throttling.

## Decision
Implement a two-tier inference strategy:
1. **Primary**: Fine-tuned `Bio_ClinicalBERT` hosted on a dedicated Vertex AI Prediction Endpoint.
2. **Standby Fallback**: Local scikit-learn TF-IDF + Logistic Regression pipeline (`maude_classifier/model/maude_classifier.joblib`), trained via `train.py` with MLflow tracking.

`app.py` enforces a startup invariant requiring `maude_classifier/model/maude_classifier.joblib`. If the primary Vertex AI endpoint fails or times out, `/classify` and `/assess` seamlessly fall back to the standby classifier.

## Consequences
- **Positive**: Resilient uptime; high-availability inference with zero external service dependency during outages.
- **Negative**: Standby predictions yield lower semantic recall on complex narrative formulations compared to the primary transformer.

# ADR 0003: RAG Chunking and EU-MDR Statutory Boundaries

## Status
Accepted

## Context
Retrieval-Augmented Generation over statutory texts (EU-MDR Regulation 2017/745) requires preserving complete statutory obligations (e.g., Article 10 QMS requirements or Article 87 reporting timelines) without splitting dependent clauses across arbitrary token windows.

## Decision
Configure `rag_pipeline.py` with:
- `DEFAULT_CHUNK_SIZE = 350` words (~450 tokens), matching median EU-MDR article length.
- `DEFAULT_OVERLAP = 50` words (~15%), preserving cross-paragraph conditional clauses.
- Vector distance space strictly configured as `metadata={"hnsw:space": "cosine"}` with `all-MiniLM-L6-v2` embeddings in ChromaDB.

## Consequences
- **Positive**: Complete legal clauses are returned with exact Article metadata and citation boundaries.
- **Negative**: Fixed-length word windowing can occasionally encompass extraneous subsections for short, single-sentence statutory articles.

# ADR 0004: Cosine Retrieval Quality Gate and Fallback Steering

## Status
Accepted

## Context
Class-steered RAG queries inject regulatory domain prefixes (e.g., `"serious incident reporting vigilance..."` for label `D`) to bias vector retrieval toward relevant articles. If a steer misses or pulls irrelevant context, unconstrained generation causes legal hallucinations.

## Decision
Enforce a hard retrieval quality threshold:
- `RETRIEVAL_QUALITY_THRESHOLD = 0.55` in cosine similarity space (`1 - cosine_distance`).
- If the top chunk retrieved by the label-steered query scores `< 0.55`, the pipeline triggers a fallback query using the unaugmented narrative text.
- Whichever pass achieves the higher cosine similarity score is returned to the user.

## Consequences
- **Positive**: Prevents label misclassifications from poisoning retrieval context; ensures high relevance.
- **Negative**: Executes a secondary vector search when the primary score is low, doubling retrieval latency for borderline queries.

# ADR 0005: Citation Containment and Grounding Verification

## Status
Accepted

## Context
Generative LLM summaries of regulatory compliance can fabricate citations (e.g., citing non-existent Annexes or inapplicable articles), creating legal and compliance exposure under EU-MDR.

## Decision
Implement strict post-generation citation containment in `rag_recommender.py`:
- All citations generated by the LLM (Gemini-3.8-flash) are checked against the explicit article metadata of the retrieved context chunks. Any citation not contained in the context is stripped.
- When `GEMINI_API_KEY` is missing or the external API call fails, the system executes a deterministic rule-based template fallback.
- The response schema enforces `llm_grounding_verified = False` whenever the template path is taken, ensuring transparent auditability.

## Consequences
- **Positive**: Elimination of hallucinated regulatory citations; clear distinction between AI-synthesized and rule-templated guidance.
- **Negative**: The model cannot reference broader regulatory context not retrieved in the top chunks.

# ADR 0006: Incremental Watermark Ingestion with GCS Persistence

## Status
Accepted

## Context
The openFDA MAUDE API contains millions of adverse event records. Fetching the full historical corpus repeatedly is rate-limited and expensive. Additionally, openFDA's skip/limit pagination breaks past 25,000 records.

## Decision
Implement date-bounded incremental ingestion in `ingestion/fetch_maude_events.py`:
- Lower bound is dynamically derived as `get_next_day(watermark)` (`[watermark + 1 day TO today]`).
- State is persisted as JSON at `gs://regulatory-copilot-506507-vertex-training/ingestion/watermark.json`.
- Fetched batches are partitioned and uploaded directly to `gs://regulatory-copilot-506507-vertex-training/data/raw/incremental/`.
- In-memory and batch-level deduplication is enforced on `report_number`.
- Secret Manager API keys are sanitized in code (BOM, whitespace, and quote stripping), and HTTP failures (4xx/5xx) fail-fast to trigger Cloud Run Job retries.

## Consequences
- **Positive**: Bounded query windows, zero redundant record fetching, resilient error reporting, and permanent data provenance in GCS.
- **Negative**: Requires GCS connectivity; corrupted watermarks require manual JSON intervention.

# ADR 0007: Human-Gated Retraining vs Continuous Auto-Retraining

## Status
Accepted

## Context
Modern MLOps often favors continuous automated model retraining upon ingestion of new delta data. However, in medical device regulatory compliance (EU-MDR Annex III, FDA 21 CFR Part 820), software making safety-critical determinations must operate under strict change control.

## Decision
Explicitly reject continuous autonomous retraining in favor of human-gated retraining:
- Ingestion runs automatically on a weekly Cloud Scheduler trigger (`0 2 * * 0`).
- Retraining requires an engineer or regulatory officer to trigger `training/train_bert.py` via Vertex AI Custom Training Jobs.
- New models must undergo offline validation, metric auditing against `reports/dataset_split_metrics.json`, and explicit promotion before updating the live Vertex AI prediction endpoint.

## Consequences
- **Positive**: Full compliance with medical device change control and validation standards; elimination of catastrophic forgetting and automated drift degradation.
- **Negative**: Model weights do not automatically adapt to novel post-market device issue vocabulary without manual intervention.
